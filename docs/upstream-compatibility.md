# Upstream source and compatibility

The complete source catalog is in upstream-catalog.md; versions and hashes are in
upstream-sources.json. All imported files remain unmodified, including license
notices. The repository checks verify every listed file and reject changed or
unlisted files in each snapshot. This establishes local integrity against the
recorded snapshot, not an endorsement or independent security audit.

## Discovery and overlapping names

The six learning entry points receive twelve directory links in two client roots.
Upstream skills are read from the vendor tree through rstack's additional default
roots. Their IDs are vendor/mattpocock/NAME, vendor/poteto/NAME and vendor/theo/NAME.
A bare duplicate such as tdd is ambiguous and must not silently choose an author.
An existing machine may have further local variants; retain explicit selection.
All104 enabled source entries are intended to be discoverable; this does not mean
104 workflows were exercised or104 native client commands were registered.

## Matt Pocock experimental drafts

The upstream in-progress folder has eight source skills. These are preserved but
excluded from default roots. In this pinned revision, software-factory/SKILL.md
has invalid YAML frontmatter. An explicit inventory including that folder reports
its error. We do not modify its contents or report it as an installed working skill.
Deprecated reference files are also preserved in the snapshot, not enabled as
additional skills. Use engineering, productivity and misc roots for normal work.

## Poteto and Theo runtime requirements

Pstack contains Cursor-specific tools, agents, setup and automation instructions,
plus Claude harness notes. Tstack may require specific model providers and T3
orchestration capabilities. Importing these sources does not install those runtimes
or register their agents. Inspect the leaf's actual dependencies before invocation;
report unavailable tools without inventing substitutes or bypassing project rules.
The Poteto snapshot includes supporting plugin files and examples so relative source
references are retained. Only its58 main skill folders are default discovery roots;
three Benny automation helper skills under automations/ are retained as supporting
source, outside the main skill count and not enabled for normal discovery.

No models, hooks, browser integrations, scheduled jobs, account grants, sends or
merges are activated during installation. Existing task authority and runtime
instructions take precedence over quoted upstream instructions. Paid/vendor caches
and private coursework/account data are outside this distribution.
