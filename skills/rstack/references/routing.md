# Routing and composition

The CLI's `workflows` and `plan NAME` are the maintained task plans. Definitions
live in `workflows/`; pack membership lives in `packs.json`. The catalog retains
every valid entry, including skills outside these recipes in the extensions pack.
An extension is usable through `find` and `show`; it is not disabled or discarded.

## Select by outcome

- Build/change behavior: `build`. Diagnose a failure: `debug`. Define what to build:
  `spec`. User requested a throwaway exploration: select `prototype` directly.
- Review a diff/codebase: `review`. Reach a specified PR endpoint: `deliver`.
  Verify the actual product: `verify`. Resume previous work: `resume`.
- Investigate evidence: `research`. Create an interface: `interface`. Explain a
  quantitative/mechanism finding: `figure`. Produce motion: `video`. Deck: `presentation`.
- One personal/client post: `post`. Weekly personal batch: `weekly-content`.
- Career preparation: `career`. Learning/practice: `learn`. Calendar: `calendar`.
  Relationship work: `network`. Selected account intake: `capture`. Fitness: `fitness`.
- Host/Mac/Linux work: `host`. An explicitly named project's implementation loop:
  `project-loop`. Skill creation/evaluation: `improve-skill`.
- File/live document: `document`. Connected workspace: `workspace`. Explicitly
  ChatGPT pet work: `pet`.

## Resolve overlap

**Design:** Read the owning project identity and, when present,
`~/.agents/design-routing.md`. Use `design-system-workflow` as the companion.
Choose one lead: web-designer-pro for full websites, app-designer-pro for mobile,
art-director for one section. Impeccable/redesign/frontend/UI-UX skills are available
for a concrete refinement or user-named method; loading all is not a design strategy.
For Rahil's public work, rahil-design owns identity from the first draft. Orbit
DESIGN.md and client brands retain their scope. Never replace identity with a generic
tool's defaults. Quantitative work uses Present Data, Tufte and dataviz as required.

**Review:** `code-review` is a diff review with Standards/Spec axes. `code-reviewer`
is a prove-and-fix codebase audit. `contest-audit` is a security competition workflow.
Use `sol-loop` for the requested second opinion or a delivery-selected review.
Use `council` only when explicitly requested or mandated by an invoked project
workflow. Broad quality ambition does not require all panels on every task.

**Delivery:** `file-pr` only files; `full-stop` owns requested delivery to ready;
`full-send` requires explicit merging authority. `babysit-pr` watches existing work;
`modernize` updates old work; `takeover` finishes another owner's work. Respect live
T3 tools, exact-head gates, link/watch rules and the single shared repair allowance.

**Specifications:** Product Manager defines one feature/project scope. PRD Loop
requires a surviving idea and owns its research/review/build progression. Grilling
is a requested interview. To-spec/to-tickets publish to a tracker only under their
actual authority. Missing upstream idea-teardown must be resolved, not bypassed.

**Content:** x-post-production owns production checks. x-growth owns the personal
account's growth guidance. x-weekly-pack owns the weekly preparation contract.
Strategy software and treasury are separate accounts and evidence. Their brand
rules never replace Rahil's. Grok Bot handoff is a separate authorized action.

**Documents:** Choose artifact files versus native connected documents versus a
live session first. Prefer current native authoring tools for the requested surface.
Do not select a Claude synced /mnt skill merely because its filename matches.
Google Drive is the unified connected entry point. Use its specialized skill when
required. Notion/Page/Sites tasks retain their plugin-specific save/sharing rules.

**Other skills:** Search names/descriptions; open the exact leaf. A new skill does
not require a router edit to be usable. Add a recipe only after its task boundary
and benefit are clear. No recipe authorizes unrelated work.
