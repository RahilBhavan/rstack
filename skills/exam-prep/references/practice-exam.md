# Practice exams

## Mirror the real exam
Derive the blueprint from the past exam(s) before writing a single question:

| Element | Take it from the past exam |
|---|---|
| Structure | Scenario-based multi-part exercises vs. standalone items |
| Question types and their mix | MC (single / select-all), matching with lettered bank, fill-in (numeric, symbolic, multi-blank words), T/F, ranking, select-from-graph |
| Points per item, total points, time | Copy them |
| Supporting material | R output, tables, graphs, code snippets: whatever the real one shows |
| Recurring exercises | e.g. a "name that procedure" matching set that appears every year |

Weight topics by how much lecture time and review-sheet space they received. State the
weighting in one line at the top of the key.

## Writing good items
- Each item tests one idea. Scenarios are 2-4 sentences of realistic context.
- **Distractors come from real mistakes**: sign errors, the wrong df, confusing r with r²,
  reversing H0/Ha, "accept H0". A distractor nobody would pick is wasted.
- Vary the surface (new contexts, numbers, graphs) while keeping the concept identical to
  what the course taught, so the student can't pass by pattern-matching the past exam.
- Include a few multi-directional items (given the output, pick the graph; given the graph,
  pick the equation). These discriminate best.
- No item should require knowledge outside the stated lectures.

## Answer key (separate section or file)
For every item: the answer, a 1-3 line justification in marking-scheme wording, and for MC
the reason the most tempting distractor is wrong. Then verify the key: re-solve each item
from scratch and fix any disagreement before delivering.

## Delivery
- Exam and key as separate sections (or separate files if the user prints them).
- Number of exams: produce one complete, verified exam before starting the next. Don't
  produce several half-checked ones in one pass.
- Offer a timed version note: "Take this in N minutes before opening the key."
